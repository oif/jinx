## 核心问题

LLM 应用（如 agents 和领域推理）越来越依赖 **context adaptation** —— 通过修改输入（指令、策略、证据）而非权重更新来适应任务。但现有方法存在两个关键问题：

1. **Brevity Bias（简洁偏见）**: 为了简洁而丢弃领域见解
2. **Context Collapse（上下文坍缩）**: 迭代重写导致细节随时间丢失

---

## ACE 框架解决方案

### 核心理念

**传统方法**: "让 prompt 尽可能短"
**ACE 方法**: "构建详细的、经验证的策略 playbook —— 让上下文随经验增长"

### 三大组件架构

```
┌─────────────────────────────────────────────────────────────┐
│                    ACE Framework                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │  Generator   │  │  Reflector   │  │   Curator    │      │
│  │              │  │              │  │              │      │
│  │ 执行任务     │→ │ 分析执行结果 │→ │ 组织策略     │      │
│  │ 产生推理轨迹 │  │ 提取教训     │  │ 更新playbook │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
│         ↓                  ↓                  ↓            │
│  ┌─────────────────────────────────────────────────┐       │
│  │              Context Playbook                   │       │
│  │  • 策略 bullets (可重用的策略单元)              │       │
│  │  • 陷阱警告                                     │       │
│  │  • 代码片段                                     │       │
│  │  • 格式规则                                     │       │
│  │  • 领域知识                                     │       │
│  └─────────────────────────────────────────────────┘       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 1. Generator（生成器）
- 使用当前 playbook 执行任务
- 产生推理轨迹（reasoning trajectories）
- 类似 Jinx 的 evolution cycle 执行器

#### 2. Reflector（反思器）
- 分析成功和失败的执行
- 提取具体的见解和教训
- 类似 Jinx 的 Reflection 系统

#### 3. Curator（策展人）
- 组织和管理 lessons
- 更新 playbook（增量添加、编辑、删除）
- **Jinx 缺失的关键组件！**

### Context Playbook 特性

- **模块化**: 由小的、结构化的 "bullets" 组成
- **增量更新**: 不是整体重写，而是添加/编辑小单元
- **防坍缩**: 保留详细知识，防止信息丢失
- **可扩展**: 随着长上下文模型扩展

## 实验结果

- **Agent 任务**: +10.6% 提升
- **金融领域**: +8.6% 提升
- **减少适应延迟和 rollout 成本**
- **无需标注数据**: 利用自然执行反馈
- **AppWorld 排行榜**: 匹配排名第一的生产级 agent，在更难的 test-challenge split 上超越它（使用更小的开源模型）

## 应用到 Jinx Evolution 系统

### 当前 Jinx 架构对比

| ACE 组件 | Jinx 对应 | 状态 |
|----------|-----------|------|
| Generator | Evolution Cycle 执行器 | ✅ 已有 |
| Reflector | `src/memory/reflection.ts` | ✅ 已有 |
| Curator | 无专门组件 | ❌ 缺失 |
| Context Playbook | `data/memory/` + prompts | ⚠️ 部分 |

### 关键差距

1. **缺少 Curator 组件**
   - Jinx 有 reflection，但没有系统化地组织和优化策略
   - 反思结果没有被结构化地存储和复用

2. **Context 更新方式**
   - 当前: 静态 prompt 模板 + 知识图谱存储
   - ACE: 动态 playbook，增量添加策略 bullets

3. **策略复用机制**
   - 当前: 依赖 memory 搜索
   - ACE: 结构化的策略集合，自动注入到 prompt

### 改进建议

#### 短期改进（低成本）

1. **创建 `data/playbook/` 目录**
   ```
   data/playbook/
   ├── strategies/     # 可重用的策略
   ├── pitfalls/       # 已知的陷阱和避坑指南
   ├── patterns/       # 成功的模式
   └── templates/      # 任务模板
   ```

2. **增强 Reflection 系统输出**
   - 当前 reflection 输出格式较自由
   - 改为输出结构化的策略 bullets
   - 例如: `[STRATEGY] 当遇到 X 时，使用 Y 方法`

3. **动态 Prompt 构建**
   - `evolution-prompt.ts` 从 playbook 动态加载相关策略
   - 而不是硬编码所有内容

#### 中期改进（需要开发）

1. **实现 Curator 逻辑**
   ```typescript
   // 新增 src/context/curator.ts
   interface StrategyBullet {
     id: string;
     category: 'strategy' | 'pitfall' | 'pattern';
     condition: string;  // 何时应用
     action: string;     // 具体策略
     evidence: string;   // 来源（哪个 evolution/任务）
     confidence: number;
     usageCount: number;
   }
   
   function curateStrategies(reflection: ReflectionResult): StrategyBullet[];
   function updatePlaybook(bullets: StrategyBullet[]): void;
   function getRelevantStrategies(context: TaskContext): StrategyBullet[];
   ```

2. **Playbook Evolution Pipeline**
   ```
   Evolution 完成
        ↓
   Reflection 分析
        ↓
   Curator 提取策略
        ↓
   Playbook 增量更新
        ↓
   下次 Evolution 使用更新后的策略
   ```

#### 长期改进（架构级）

1. **多层级 Playbook**
   - Working Playbook: 当前任务相关
   - Short-term Playbook: 最近学习的策略
   - Long-term Playbook: 经过验证的核心策略

2. **策略验证机制**
   - 新策略需要多次验证才能进入 long-term
   - 类似 memory 的 consolidation 机制

3. **跨任务策略迁移**
   - 识别可复用的策略模式
   - 自动应用到新任务

## 关键启发

### 1. Context 是第一优先级资源
- ACE 证明了：不需要权重更新也能实现自我改进
- Context 的演化和组织是核心能力

### 2. 结构化优于自由文本
- Playbook bullets 比自由文本记忆更可操作
- "条件 → 策略" 的结构便于检索和应用

### 3. 三角架构的稳定性
- Generator（执行）、Reflector（分析）、Curator（组织）形成闭环
- 单独的 reflection 不够，需要 curator 来系统化管理

### 4. 防止 Context Collapse
- 增量更新而非整体重写
- 保留细节，不要为了简洁而丢弃关键信息

```typescript
【避坑指南】
${recentPitfalls.map(p => `• ${p.condition}`).join('\n')}

...
`;
```

## 结论

ACE 论文提供了一个清晰的框架，将 LLM 的自我改进从"静态 prompt"提升到"演化 playbook"。对 Jinx 的核心启示：

1. **Context 管理 = 自我改进能力**: 不需要模型训练，只需要更好地组织和演化 context

2. **Curator 是关键缺失**: 当前系统缺少专门的策略组织机制

3. **结构化策略**: 将反思转化为可复用的策略单元

4. **增量演化**: 防止信息丢失，保持详细知识
